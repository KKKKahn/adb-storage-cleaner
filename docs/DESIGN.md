# 设计说明

## 目标与非目标

**目标**

- 在无 Root 的 Android 设备上，尽可能完整地盘点 `/sdcard`。
- 把“空间去哪了”解释清楚，而不只是给一个“可清理 XX GB”的数字。
- 删除行为可预测、可审查、可追溯。
- 跨厂商、跨平台（macOS/Linux/Windows），只依赖 Python 标准库和 `adb`。

**非目标**

- 不做“一键加速”“内存清理”“病毒扫描”。
- 不绕过 Android 的权限模型。
- 不读取 `/data/data`（需要 Root）。
- 不支持 iOS。

## 扫描：为什么用 `du -ab`

候选方案：

| 方案 | 问题 |
|---|---|
| `find /sdcard -type f -printf '%s %p'` | toybox `find` 不支持 `-printf`；部分设备没有 GNU find |
| `find ... -exec stat {} +` | 文件多时触发 `Argument list too long`，扫描中断 |
| `stat` 逐文件 | 每个文件一次进程，十万级文件不可接受 |
| **`du -ab`** | 单进程、一次输出、toybox/busybox 都支持；代价是 apparent size |

`du -ab /sdcard/` 输出格式：

```text
4096\t/sdcard/
2048\t/sdcard/DCIM
1024\t/sdcard/DCIM/IMG_0001.jpg
```

解析后按路径排序，若下一条路径以 `当前路径 + "/"` 开头，则当前路径是目录。这样不需要额外的 `stat`。

### 符号链接陷阱

`/sdcard` 本身是指向 `/storage/emulated/0` 的符号链接。`du -ab /sdcard`（不带尾斜杠、不带 `-L`）可能只输出链接本身。工具始终传入 `/sdcard/`（尾斜杠），确保遍历挂载点内部。

### 限制

- **apparent size**：`du` 默认统计文件逻辑大小，不考虑压缩、稀疏文件、块对齐，因此和 `df` 的“已用”不完全一致。
- **文件名中的换行/反斜杠**：`du` 默认不转义，解析会不可靠；MD5 阶段会跳过 `md5sum` 标记为转义的行。这类文件名在手机上极罕见。
- **权限**：部分 OEM 限制 shell 访问 `/sdcard/Android/data`，工具只能报告看得到的部分。
- **速度**：十万级文件约 30–120 秒，取决于 USB 速率和存储芯片。

## 分类

按扩展名分为：图片、视频、音频、文档、压缩包、安装包、其他。

这个分类只用于报告，不参与删除决策。删除决策完全由**路径白名单**和**MD5**决定。

## 垃圾目录白名单

“缓存”这个词太宽泛。工具只认目录名的完整段匹配：

```python
CACHE_SEGMENT_RE = re.compile(r"(?:cache|caches|.*cache.*|.*thumb.*|tmp|temp|logs?)", re.I)
```

并且必须位于：

- 相册的 `.thumbnails`；或
- `/sdcard/Android/data/<包名>/` 之下，且不是包名根目录。

`catalogs` 不会被 `logs?` 匹配，`galleryOriginal` 不会被 `.*thumb.*` 匹配。

选中目录后，工具会折叠嵌套目录：只删最外层匹配项，避免重复计算和重复删除。

## 精确去重

### 为什么先按大小分组

MD5 相同 ⇒ 大小必然相同。先按字节大小分组，可以把需要哈希的文件从数万个降到几百/几千个。

### 设备端哈希

```bash
md5sum 'path1' 'path2' ...
```

每批 20 个文件，避免命令行过长。输出格式：

```text
d41d8cd98f00b204e9800998ecf8427e  /sdcard/DCIM/a.jpg
```

以两个空格分隔。`md5sum` 对含换行/反斜杠的文件名会在行首加 `\` 并转义，解析器会跳过这些行（宁可不删，不可误删）。

### 保留策略

`keep_score()` 返回一个排序元组：`(层级+惩罚, 路径深度, 路径长度, 路径)`，越小越优先保留。

层级：

```text
DCIM=0, Pictures=10, Movies=15, Music/Documents=20,
Download=40, 其他=50, Android/media=60, Android/data=80,
vivoMediaData=95
```

惩罚：

- 二手/导入目录（互传、办公套件、聊天应用、备份、副本…）+25
- 隐藏目录 +30
- 缓存/缩略图 +60

### App 数据保护

`is_auto_deletable_app_file()` 只允许删除 `Android/data/<包名>/` 中**缓存类目录**里的副本。相机原片、数据库、媒体库默认不自动删，因为应用可能用数据库索引它们，删掉文件名可能导致索引失效。

### 删除前校验

默认重新计算每组保留副本的 MD5。如果保留副本变化或消失，整组跳过。这样即使扫描后文件被修改，也不会误删唯一副本。

## 动态照片

### 识别

```text
^IMG_(\d{8})_(\d{6})\.mp4$
```

加上同名 JPG 存在。`Videoshot_*` 是录屏（同名 JPG 只是缩略图），`IMG_*_1.mp4` 是编辑/导出，二者都排除。

### 时长过滤

通过 MediaStore 读取：

```bash
content query --uri content://media/external/video/media --projection _data:duration
```

正常动态照片约 1–3 秒。默认只处理 ≤5 秒的文件；4–8 秒的会单独列出；超过 8 秒的基本可以确定是真实视频，不处理。

查不到时长的文件默认跳过（`--include-unknown` 可包含），因为无法排除“误命名为 IMG_ 的短视频”。

### 为什么系统把它算进“其他”

动态照片的主文件是 JPG，MP4 是附属物。很多系统在统计时：

- 不把 MP4 算进“视频”（因为它不是独立视频）；
- 也不把 MP4 算进“图片”（因为主文件是 JPG）；
- 最后只能归入“其他文件”。

这是统计口径问题，不是垃圾文件。工具的报告会单独列出这部分，帮助解释设置页的数字。

## 报告

- Markdown：便于 diff、粘贴、归档。
- HTML：单文件、内联 CSS、支持深色模式，适合直接打开阅读。
- 十进制单位，与手机设置页一致。
- 序列号脱敏。
- 报告只写本地，不含文件内容。

## 测试策略

- 纯函数单测：分类、白名单、保留策略、`du` 解析、MD5 解析、动态照片识别、报告渲染。
- 不依赖真机的测试可以在 CI 跑。
- 破坏性函数（`apply` / `delete`）通过脚本拼接测试和人工真机验证；CI 不连接设备。
